BEFORE the fix, the same executor printed:
    Segmentation fault (core dumped)      exit 139

Root cause (two defects, fixed together):

1. shellcode.ld opened `. = ALIGN(16)`, starting the address counter at 0, so
   the first LOAD segment sat at vaddr 0. Linux refuses to map below
   vm.mmap_min_addr (65536) -> execve = -1 EPERM before _start ran.
   Fix: . = 0x400000;

2. objcopy -O binary dumps from the lowest VMA, and ld's default
   -z separate-code put read-only data in its own LOWER-addressed segment.
   So shellcode.bin began with "hello world\n" (ascii) and the executor
   executed string bytes as instructions -> SIGSEGV.
   Fix: -Wl,-z,noseparate-code (one segment) AND collect
        *(.rodata .rodata.*) after *(.text._start) in the linker script.
        The bare *(.rodata) glob never matched Rust's actual
        .rodata..Lanon.<hash>.0 section name.
